other.

tooltip =
manpage = Command file for CTF correction, which can be entered with or

[Field = NumberOfSlabs]
short = slabs
type = I
usage = Number of reconstructions to make at different depths in Z
tooltip =
manpage = Number of reconstructions to make at different depths in Z with
different corrections for CTF.  Either this option or \fB-thickness\fR must be
entered, but not both.  This entry must be at least 3.

[Field = SlabThicknessInNm]
short = thickness
type = I
usage = Maximum thickness of reconstructions at different depths, in nanometers
tooltip =
manpage = The maximum thickness of reconstructions at different depths, in
nanometers.  This value, if entered, must be less than half of the tomogram
thickness so that at least 3 three slabs are computed.

[Field = RunSlabsInParallel]
short = parallel
type = B
usage = Make each slab with one processor or GPU
tooltip =
manpage = Make each slab with one processor or GPU by creating a chunk file containing
both the Ctfphaseflip(1) and Tilt(1) commands.  This arrangement is the most
efficient if there are more slabs than GPUs or processors, but requires more
storage, as there will be as many created aligned stacks as processors.  The
default is to make each slab sequentially, with parallel processing (if any)
used to create the aligned stack then reconstruct the slab.  In this case only
one corrected aligned stack exists at any time.

[Field = NumberOfProcessors]
short = procs
type = I
usage = Target or expected number of CPUs or GPUs (default 8, or 1 if GPU is used)
tooltip =
manpage = Use this option to specify the number of processors or GPUs that you expect to
run the command files on.  It is appropriate only when computing slabs
sequentially and cannot be entered with the \fB-parallel\fR option.  It is
passed directly to Splittilt(1) unless it is 1, in which case the processing
is not divided into chunks.  The default is 8 unless the Tilt command file
contains the option to use the GPU, in which case it is 1.

[Field = ChunksPerProcessor]
short = perproc
type = I
usage = Number of chunks per processor (default 3)
tooltip =
manpage = Use this option to set the number of chunks per processor when
correction and reconstruction are divided into chunks; it will
be multiplied by the number of processors to give a value for the
\fB-TargetChunks\fR option to Splittilt(1) and used to determine the number
of slices to be corrected per chunk in Splitcorrection(1).  The default is 3.
